## Open issues
- **32.11% of links reach no article, even after following redirects** (re-measured 2026-11-11
  with redirect chains resolved from `redirects.jsonl`):
  - 32.06%: target is neither an article nor a redirect. These are "red links" (titles that only
    exist on English Wikipedia) and links to skipped disambiguation pages.
  - 0.05% (3,183 links): target is a redirect whose final target is not an article.
    1,822 of the 115,575 redirects end at a non-article, mostly disambiguation pages.
  - Redirect chains are rare: exactly 1 link needed 2+ hops. No redirect loops were found.

  This is real data, not a parser bug (only 0.3% would match if case were ignored).
  PageRank (Phase 4) must follow redirects and then drop links whose final target is not an article.
- **Ranking weak spots left** (after PageRank): questions whose answer is not named in the query (held-out MRR
  0.060 keyword, 0.112 Smart); redirect-only abbreviations ("usa" #1,702 keyword, #172 Smart; "uk" #54 / #107)
  → alias field retry in Phase 6.
- ~~Smart vs keyword is a near tie~~ **Resolved 2026-11-13** by the fix experiment: Smart 0.956 vs keyword 0.868
  on the main 50, and Smart no longer loses any exact-title category. The variant was *selected* on these 50
  queries (10 configs compared), so 0.956 is optimistic. The honest unseen number comes from
  `queries-holdout-v2.json` in Phase 6.
- **Still weak in Smart:** "usa" #5 (keyword #1,702) and "what is the capital of australia" (Canberra) #9.
- **HNSW recall is lower than typical published numbers** (bge-60: 0.830 at efSearch 50). Queries are short titles,
  documents are passages (different "shape"), which is harder for HNSW. The rule picked efSearch 400
  (1.5 ms per search, still tiny next to the 2.5 ms query embedding).
- **int8 + HNSW recall is 0.948 at efSearch 400** (float32 0.957). The efSearch rule is applied to float32, as
  pre-registered. MRR is identical for int8 and float32 (0.956), so int8 stays for the memory saving.
- **The bge 200-word embedding (variant E) took 36.8 h wall-clock** because the Mac slept with the lid closed
  during the run. It is not a speed measurement and is not quoted as one. The vectors are fine (count and title
  hash match).
- The old MiniLM files (`data/model`, `data/vectors`, `data/vectors-minilm60`, `data/vectors-bge200`) are no
  longer used by the server. They stay in `data/` (git-ignored) only for re-running `fix-variants`.
- **int8 is not faster in Java** (brute force 30.6 vs 26.0 ms): reading bytes one by one from a ByteBuffer costs
  more than it saves. It still saves 307 MB of memory, which matters for hosting.
- **Spelling misses** (3 of 15): misspellings that occur in 5+ articles count as known words ("goverment",
  "medecine"); "elefant" → "elegant". Not tuned after seeing the typo set. Write new typo queries before changing rules.
- **The MRR is tuned on the 50 main queries.** Report the held-out number (0.763) next to it. The held-out 20 have
  now been looked at three times (final ranking, alias peek, PageRank sanity): write a fresh set in Phase 6
  before any new tuning.
- ~~Run the CLI on Java 21~~ **Fixed 2026-11-11:** `scripts/sift-cli` runs the CLI on Gradle's Java 21; the CLI warns on any other version.
- **3,496 of 280,748 articles (1.25%) keep a little markup** (any of `[[ ]] {{ }} | < '' ==`), mostly
  from broken source wikitext or articles that show markup as examples. This is acceptable: the
  tokenizer splits on non-letters anyway. It is an upper bound, because a `|` can be legitimate text.
- **Many short articles:** the median is 72 words. Confirmed in Phase 1: length normalisation strongly
  favours short articles (see the ranking issue above).
- Links found inside `<ref>` citations are kept in `links` (the citation *text* is removed).
  This has a minor effect on PageRank. Revisit only if PageRank looks odd.

- **`text.bin` is 267 MB uncompressed** and the whole index folder is 409 MB. Decide in Phase 7 (Docker image,
  Cloud Run memory) whether to compress the text per article or keep only the first N words.
- **The alias setting was seen on the held-out set.** The disk-vs-memory check also ran "final + alias bonus"
  on the 20 held-out queries as a file-format test (0.764 vs 0.697 without). Nothing was changed because of it,
  and the ranking stays locked, but those 20 queries are no longer "unseen" for the alias question.
  Phase 6 needs a fresh held-out set before retrying aliases.

## Phase 5 fix: one pre-registered experiment (decided 2026-11-12, written BEFORE any run)

**About the old held-out check.** It failed by one query ("narwhal" #1 → #2: 0.763 vs 0.748). With only
20 queries one rank flip moves MRR by 0.025, so "Smart must not be lower" was too strict a rule for 20 queries.
**We do not re-run the old held-out 20 again.** The untouched `eval/queries-holdout-v2.json` gives the final
verdict in Phase 6 and is never run before then.

**Variants** (semantic part evaluated with EXACT brute-force search, not HNSW):
- A. all-MiniLM-L6-v2, title + first 200 words (the current vectors)
- B. all-MiniLM-L6-v2, title + first ~60 words
- C. all-MiniLM-L6-v2, two vectors per article (B + A), similarity = max of the two
- D. BAAI/bge-small-en-v1.5, title + first ~60 words, with the model's recommended query instruction prefix
- E. bge-small-en-v1.5, two vectors per article (60 + 200 words), max similarity

For D/E: export to ONNX, re-run the tokenizer check (1,000 strings, exact ids) and the Java vs Python
embedding check (cosine ≥ 0.9999). If bge's tokenizer differs from my WordPiece, adapt and re-verify.
If either check cannot pass, D/E are dropped.

**Fusion** for each variant: plain RRF (k = 60) and keyword-weighted RRF (keyword list weight 2).

**Selection rule** (main 50, hybrid mode, int8 vectors):
1. Highest overall MRR wins.
2. Within 0.01 of the best = tie → prefer one vector over two, MiniLM over bge, plain RRF over weighted.
3. Report whether "how do plants make food" puts Photosynthesis in the top 3, but do NOT use that query to choose.

**Then, for the winner only:** HNSW (M 16, efConstruction 200), efSearch = smallest with recall@10 ≥ 0.95,
int8 recall vs float32 ≥ 0.97, Smart p95 over HTTP and server memory, make it the Smart default
(keyword mode unchanged). Done when: winner locked, all tests pass, Smart p95 < 100 ms. If Photosynthesis is
still not top 3, it is documented as a known limitation, with no further tuning.
